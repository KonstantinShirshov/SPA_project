В мире развивается тренд на онлайн-обучение. Но для веб-разработчика важно не только обучиться, но и знать, как
реализовать платформу для онлайн-обучения. Поэтому новая задача касается разработки LMS-системы, в которой каждый
желающий может размещать свои полезные материалы или курсы.

Ранее в проектах мы могли сразу видеть визуальное отображение результата разработки, теперь работа будет над SPA
веб-приложением и результатом создания проекта будет бэкенд-сервер, который возвращает клиенту JSON-структуры.

В проект добавлены модели курса, урока, подписки, платежа, и пользователя.

Основные эндпоинты работы CRUD курсов и уроков и функционал работы подписки протестированы при помощи unittest.  


### Требования

* Python 3.10+
* Docker, Docker Compose (для запуска в контейнерах)
* Poetry (для локальной разработки)

### Запуск проекта на локальной машине

1. Установите Docker и Docker Compose, если они ещё не установлены.
2. В терминале, перейдите в директорию проекта.
3. Запустите команду: docker-compose up --build -d

### Проверка работоспособности

- **Бэкенд**: Откройте браузер и перейдите по адресу `http://localhost:8000`.
- **PostgreSQL**: Подключитесь к базе данных через pgAdmin или другой клиент.
- **Redis**: Используйте `redis-cli` для проверки подключения.
- **Celery** и **Celery Beat**: Проверьте логи в терминале, чтобы убедиться, что задачи выполняются без ошибок.

### Деплой

## Локальная настройка
Добавить SSH ключ на сервер: ssh-copy-id deploy@server_ip
Проверить подключение: ssh deploy@server_ip

## GitHub Actions

Workflow запускается автоматически при пуше в ветку main.

# Ручной запуск:

1. Перейти в Actions → "Deploy to Server"
2. Нажать "Run workflow"
3. Выбрать ветку main

# Что делает workflow:
* Установка зависимостей
* Запуск тестов 
* SSH-подключение к серверу  
* Пулл изменений 
* Установка зависимых пакетов
* Остановка текущих процессов
* Сборка контйнеров и запуск проекта в контейнерах

# Переменные окружения
Добавить в секреты GitHub:
* SSH_PRIVATE_KEY — приватный SSH ключ
* SERVER_IP — IP сервера
* DEPLOY_USER — имя пользователя (deploy)
